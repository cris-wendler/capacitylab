Local database lab

The lab loads the synthetic retail dataset into a disposable MySQL 8.0 or PostgreSQL 17 container and runs the scenario's statement mix with many concurrent connections. It runs the same arrivals through several phases (baseline, the event with the batch job, the event with a candidate index, the event with the batch job moved) and records what the engine actually did.

  • Client latency per statement (p50, p95, p99) and queueing delay
  • Statement statistics: performance_schema digests on MySQL (rows examined, temporary tables), pg_stat_statements on PostgreSQL (buffer blocks, blocks read from disk)
  • Lock waits, deadlocks, running sessions and database load
  • Plans with estimated and actual rows: EXPLAIN ANALYZE, or EXPLAIN (ANALYZE, BUFFERS) with blocks per step
  • MySQL only, optional Percona Toolkit checks: pt-query-digest on each phase's slow log, pt-duplicate-key-checker while the candidate index exists, pt-deadlock-logger, pt-variable-advisor, and pt-mysql-summary

Measurements describe this synthetic workload on one local container. They are useful for comparing phases with each other, not for predicting production performance.
